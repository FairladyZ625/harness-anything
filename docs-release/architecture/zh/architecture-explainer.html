一次命令，多个可独立观察的进度

每个仓库的 SQLite generation 1 台账是唯一接受点。命令持久接受后，投影、Git 文档和工作树分别推进；回执明确区分这些进度。

1 · RepoCell 排队中心 daemon 校验请求、权限、幂等键和 writer epoch。边缘节点向中心提交请求。
2 · SQLite 接受所需对象先完成文件和目录同步。一个 BEGIN IMMEDIATE 事务校验 writer lease，并提交完整成员事件与 command outcome。
3 · 消费已接受事件可重建投影读取台账。异步 Git publisher 从事件推导 authored documents、退役路径和段清单。
4 · 独立回读Git 内容、mode、退役路径和清单通过回读才获得 verified。工作树另行比较、写入和回读，并保留用户改动与 index。

回执回答什么

字段 含义
status accepted_durable、rejected 或 unknown；接受依据来自已提交 command outcome。
acceptance SQLite/local_fsync、成员操作 ID、起止 revision，以及含 repoId/generation/revision/headDigest 的 cut。
projection / git / worktree 各消费者独立报告 verified cut 或 pending。一个消费者失败不会抹掉已经接受的事务。
replica 没有配置验证时报告 not_configured；本次换代不引入 generation 2 或 FleetCut generation。
wait 等待选定回执谓词。超时报告尚未满足的条件，保留原接受事实。

ha receipt show <op-id> --wait accepted_durable,git_verified --timeout-ms 60000 可观察同一操作。Git pending 时使用原操作 ID 查询，避免把可见性延迟变成另一条命令。

读取与重建

事件读取直接来自 ledger.sqlite，包括按操作 ID、revision 和批次读取。投影 SQLite 是可丢弃的派生索引；接受台账与其所需 objects 是必须备份的原始数据。Git 只保存 authored documents 和段清单，无法单独重建所有已接受事件。

历史转换与切换

旧 Git 前缀和已接受业务 WAL 后缀在停止写入后被固定为不可变 generation-0 快照。已知历史转换仅导入未激活的 generation 1；原始字节保留。严格转换校验和零待转换 preflight 通过后才能激活。生产中的历史原地重写命令已退役。

独立 reconcile 比较固定导入源、台账元数据、行摘要、命令结果、对象字节和实际 Git 回读。生产切换还需要备份、恢复演练、日常备份 Schedule、两个一致冷重建、canary 回执和 CEO 运维记录。备份后的新接受记录必须保留；恢复 Git tag 本身无法回滚 SQLite 接受。

可核查的实现入口

  • packages/daemon/src/repo-cell.ts：RepoCell 接受组合与 daemon writer fence。
  • packages/kernel/src/store/sqlite-event-store.ts：事务、事件、command outcome 与 writer lease。
  • packages/kernel/src/store/sqlite-task-event-store.ts：事件驱动的 Git 和工作树消费者、独立回读。
  • packages/kernel/src/composition/receipt-acceptance.ts：从持久结果与独立消费者组装 D4 回执。
  • packages/kernel/src/store/legacy-generation-conversion.ts：停止写入后的原始导入与激活 preflight。
