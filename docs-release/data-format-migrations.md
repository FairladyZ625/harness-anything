# Persisted format migrations

A persisted format change ships an attach migration registration and frozen historical sample tests in the same change. The daemon applies each registered step once, records it in the event stream, and only then opens the projection. Runtime readers normalize only the named historical fields owned by a registered step.

| Persisted data                                                                    | Conversion boundary                                                                                                                                                                                                                                                                                                                                                                                                                                                         |
| --------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Generation 1/2 ledger, historical task snapshots                                  | `ha migrate ledger --help`: backup, dry-run, isolated conversion, verification, activation; preserve the source and report unsupported history.                                                                                                                                                                                                                                                                                                                             |
| Repository vertical declaration or installed vertical resource                    | `ha migrate completion --source <file> --mode dry-run`, then `--mode convert --destination <new-file>`. Review the candidate; repository declarations require acceptance through `ha doc sync --submit --path harness/vertical.json` and a reopen.                                                                                                                                                                                                                          |
| Installed preset object and active pin                                            | Read the digest from `presets/active/<id>.json`; use `ha migrate completion --source <presets/preset-objects/digest> --mode dry-run`, then `--mode convert --destination <new-directory>`. Review the candidate and run `ha --root <repository> preset install --source <candidate-directory>`. The center repository writer queues installation and moves the pin; the original object remains untouched.                                                                  |
| Authored settings, historical settings events, and accepted vertical declarations | The daemon attach path records retired CI settings and hosted completion-source steps before opening reads. Historical event snapshots are normalized during projection replay; authored `harness.yaml` reads and the next settings write remove only registered retired CI fields while preserving its original blob and unrelated settings. Accepted vertical declaration blobs remain immutable and their parsed values are normalized at the declaration read boundary. |
| Authored agent declarations with retired `runtime_type` / top-level `model` fields | `ha migrate agent-declaration --source <file-or-agents-directory> --mode dry-run`, then `--mode convert --destination <new-path>`. Conversion preserves the source; declarations naming runtime kinds or models without an enabled instance on this node still convert and the receipt reports the exact install-time issue. Reinstall each reviewed agent with `ha agent install --source harness/agents/<id>.json`. |
| Local settings                                                                    | Convert the external file explicitly when its format changes; no generic conversion or automatic defaults.                                                                                                                                                                                                                                                                                                                                                                  |
| Daemon writer-epoch authority                                                    | After stopping daemons that use the user root, run `ha migrate writer-epoch`. The command copies each repository's maximum epoch from the old `writer-epochs.sqlite` current/history rows into `writer-epochs/<repoId>.sqlite`; the floor includes current lease version to preserve version-based idempotency keys. It records `PRAGMA user_version=1` only after all repo floors are imported. Daemon attach refuses a repo whose floor is unreadable or has not been imported, with a repo-scoped recovery instruction. This preserves the fence floor for `remote-edge`, whose local ledger floor is zero. |
| Squad run identity on historical runtime events                                   | The attach path registers `squad-run.subject` for the retired flat `taskId` / `executionId` on Squad runtime events. Replay normalizes it in memory, so stored bytes stay unchanged, and replay projections derive summary identity and Task / Execution / Schedule / occurrence entity refs from `subject`.                                                                                                                                                                |
| Historical task-review runtime dispatch keys                                      | The daemon attach registry records `runtime.reviewDispatchKey` once for a reviewer dispatch with the legacy `task-review:<task>:<execution>:<iteration>:<submission-digest>[:attemptN][:fallback:N]` shape. Projection replay inserts `:reviewer:<agentId>` after the digest and keeps any attempt or fallback suffix. Event/op, dispatch, and runtime-session identities are unchanged; the conversion no longer matches once qualified, and the attach marker prevents a second migration event. A projection schema bump rebuilds existing caches from retained event history. |
| Derived SQLite projections and replica state                                      | Rebuild from continuous accepted history using the existing generation/schema invalidation path. Preserve future-version and history-gap failures.                                                                                                                                                                                                                                                                                                                          |

The completion converter recognizes the retired `software-coding-standard` vertical declaration and `standard` / `software-coding-standard` preset profiles. It preserves explicit completion declarations and unrelated content. Custom checker profiles require an explicit mapping and are rejected. Missing completion on an unrecognized vertical is rejected. A preset manifest does not require its own completion override.

The agent declaration converter recognizes the pre-runtimes shape (`runtime_type` string plus optional top-level `model`) and rewrites it to the current `runtimes` rows, carrying every still-supported field verbatim. It never guesses: a declaration with both shapes, a `model` without `runtime_type`, a retired `fallback` block, or any residual schema violation is rejected per file with its issues, and one bad file never aborts the batch. Runtime availability stays advisory — the declaration keeps the author's runtime kind, and the receipt reports the same install-time check (`agent_runtime_type_unavailable` / `agent_model_unavailable`) the node would raise, or `runtimeAvailability: unknown` when no instance store is readable.

Declaration conversion writes a new file and never overwrites the input or accepted history. Copy the reviewed repository candidate to `harness/vertical.json`, submit it with the command above, and reopen before continuing writes. Offline conversion never activates a pin. Concurrent edge installation requests use the same center RepoCell write queue; edges are not independent preset writers. The candidate must be accessible to the center installer. Updating a preset pin affects subsequent resolutions, not frozen task snapshots. A repository whose historical ledger cannot open must use the ledger conversion path; an online document append is not evidence of historical replay.

Historical samples live in `packages/preset/fixtures/completion-migration/`. Guidance tests and isolated integration tests cover the old decoder failure, explicit CLI migration, active catalog/resolution, preserved source bytes, idempotence, rejected unknown formats, and repository acceptance/reopen. They run through the existing tier manifest; no additional CI gate or compatibility reader is introduced.

## Real old-data copy evidence in one command

The "new code starts and reads a real old copy, and a full cold rebuild succeeds" leg of a
migration review is produced by a single command, never by hand-assembled copies:

```sh
node tools/old-data-copy-evidence.mjs [--source <repo-root>] [--build <worktree|sha>]
```

Run it from any checkout of this repository. It snapshots the live source workspace into a
system temp directory (git local clone of `harness/`, APFS clone of `store/generations`, then
read-only `VACUUM INTO` snapshots — projections first, ledger last, so the copied projection
can never be ahead of the copied ledger), starts an isolated daemon under a fresh user root
and daemon id so the production daemon and its data are untouched by construction, registers
the copy, waits for the daemon's own `repo_attach_completed` lifecycle record, stops the
daemon, reads through the build's production functions, cold-rebuilds the projection from
zero, and prints one JSON receipt: build commit (`loadedBuildId`), source revision, attach
record with duration, rebuild watermark and `stateDigest`, peak RSS of both the daemon and the
rebuild process, and the raw error of whichever phase failed. `--build` accepts a worktree
path or any revision; a revision is checked out and built in a temporary worktree. The command
already strips dispatched `HARNESS_*` and provider credentials from the daemon environment
(local identity is the sanctioned way to attach a temporary copy) and sets the production heap
ceiling, so a dispatched worker runs it without touching their environment. Temporary files
live under the system temp directory and are removed when the command finishes; pass `--keep`
to keep the copy, and `--reuse-workspace <ws>` to run a second build against the same copy
(the negative-control shape: identical data, only the build differs).
