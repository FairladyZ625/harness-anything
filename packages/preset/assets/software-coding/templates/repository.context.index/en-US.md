# Repository Context

This directory routes durable context that helps contributors understand and change the repository.

## Architecture

Use `architecture/` for system boundaries, components, and structural intent.

## Development

Use `development/` for local setup, code navigation, and external development context.

## Integrations

Use `integrations/` for API, event, webhook, and vendor contract entry points.

## Research

Use `research/` for sourced investigations. Tasks, decisions, and standards remain in their canonical repositories rather than under context.
