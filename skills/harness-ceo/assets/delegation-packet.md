# 委托任务包

把以下章节放入现有权威任务计划。运行时从计划派生执行指令时，不另维护重复版本。执行前填实占位内容；缺少实质信息时先查可用来源，再升级。

## 背景

- 原始来源与适用指令（具体章节或锚点）：
- 用户知识索引及本次相关问题、矩阵、接受风险的落点：
- 源码、权威文档和运行态各自的可访问根：
- 工作意义与首个使用方：
- 当前状态、已有实现、未验证前提：
- 关联工作与集成上下文：

## 请求

- 分配角色、上级与集成负责人：
- 本次类型：只设计 / 只调查 / 只复核 / 实现 / 简化，不得静默转换：
- 可观察目标与非目标：
- 验收行为、真实使用方、验证环境与所需检查层次：
- 上级给出的哪些前提只是推论，允许如何证伪：

## 输出

- 交付物与使用方入口：
- 运行时或中心分配的本次执行产物落点：
- 最终结果：结论、变更路径、直接验证、缺口、风险、身份：

## 约束

- 职责与预期源码范围：
- 并发持有人、冲突路径、保护面：
- 已授动作与所需审批：
- 所选运行时与模型、矩阵条目和版本，或尚未测量的选型：
- 任务认领、执行权限与中心写入路径：
- 已有预算与相关限制（不得编造令牌预算）：

## 检查点

- 当前角色的交接条件与必需验证：
- 何时将实质范围或权限问题交回上级：
- 如何报告错误前提，包括证据与替代方案：
- 在飞执行监管负责人，以及会话丢失时的交接方式：
