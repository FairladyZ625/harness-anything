# 问题与反馈观察

使用工作区已有问题格式时，将这些信息映射进去，不另建重复记录。原始证据放本次执行产物；后续归并使用引用。

## 观察

- 用户实际反馈或观察到的现象：
- 发生的任务、执行与阶段：
- 预期结果与实际结果：
- 影响范围：
- 环境、运行时、模型与版本（未知则标明）：
- 原始证据及可复核方式：

## 判断

- 已核实事实：
- 尚未验证的解释：
- 已查询的同类问题、任务、接受风险：
- 本次相对已有记录增加了什么观察：
- 最小区分实验及结果，或缺少什么条件：

## 处置与归宿

- 对应知识位置：用户约定 / 模型矩阵 / 运行时问题 / 项目问题 / 通用方法：
- 已有关联记录或需要新建的候选：
- 已授权范围内的当前动作与负责人：
- 临时办法（若有）、适用条件和撤销触发条件：
- 解决或接受依据、验证结果：
- 必须改写或删除的旧建议：

用户反馈不等于已经证实根因。未确认偏好不扩大权限，记录候选也不等于承诺立即修复。避免写入无关私人内容和凭据。
