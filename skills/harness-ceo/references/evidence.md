# 取证纪律：识别会误导判断的观测面

适用：复核执行者报告、解释没有发现、判断性能改善、归因测试失败、验收新检查。不是每次操作都跑下列全部检查；选择结论实际依赖的观测面。

## 十六类误判与对应动作

| 观测面 | 可能误判 | 判读前的具体动作 |
| --- | --- | --- |
| 1. 写入回执 | 把受理、预演生成的标识当作真实写入 | 回读实际实体或产物，核对内容、版本及是否只是预演；不能只看成功字样 |
| 2. 变更片段 | 看见新增规则，却漏掉全文里仍生效的旧规则 | 阅读所在整节、调用方及同类定义；检查是否出现重复权威 |
| 3. 分页结果 | 把一页当成全集，累计量随窗口滑动而下降 | 检查分页游标和筛选范围；穷尽任务用完整分页或聚合入口，标出未覆盖范围 |
| 4. 运行快照 | 在执行者尚未提交时指责其遗漏 | 先区分运行中、检查点、已退出及已交接；只在稳定产物上判定最终交付 |
| 5. 单个执法面 | 修改一个规则位置后就宣布约束已一致 | 列出本约束的实际生效来源，逐一核对；平台保护、队列条件和仓库检查可能共同生效 |
| 6. 检测器沉默 | 未执行、扫错路径、参数被 shell 改写却被读成零问题 | 用已知应命中的输入验证搜索或检测入口；核对输入范围和执行版本 |
| 7. 单次测量 | 把调度、争用和随机波动当成性能信号 | 在可比条件下取得独立样本，比较差异与波动；不确定时不宣布提速或退化 |
| 8. 手维护清单 | 对着旧门集、旧诊断实现已经存在的功能 | 从现行权威配置发现检查；修已知问题前复核原诊断与原场景，不只看状态标签 |
| 9. 错误入口 | 拿另一二进制、实例或账号的真实报错给目标系统定罪 | 核实实际入口、版本、实例与公开身份信息，再做授权范围内的最小请求；不输出凭据 |
| 10. 不可见来源 | 工作树缺少被忽略目录，却报全量扫描零问题 | 明确源码、权威文档、运行态的不同根；验证实际可读性，缺权限就标缺口，路径可读不等于有写权 |
| 11. 共享可变缓存 | 并发构建污染被归因成源码错误 | 查并发进程及共享路径；在隔离缓存或串行条件复跑区分原因，不预设所有缓存不支持并发 |
| 12. 只测形式 | 常量、字段或开关正确，但进程、内存、耗时后果失控 | 明确伤害发生的量纲，检查生命周期、资源释放、下游结果；形式断言不能替代后果验证 |
| 13. 测量装置变形 | 字符串参数未按预期分词、管道退出码覆盖被测命令 | 使用参数数组或正确引号，分别保存输出与错误，紧接被测命令取得退出码；矛盾读数先核查调用方式 |
| 14. 检查量程不足 | 定向检查绿被解释成所有影响面已验证 | 沿调用链判断失败会落在哪个层次，补受影响且必需的检查；另列非阻塞检查的真实失败与负责人 |
| 15. 监视器自计数 | 进程匹配把监视器本身或辅助进程算成执行者 | 优先使用执行身份和真实 PID；检查完整命令行及进程归属，不只看聚合数量；远程看不到不等于进程死亡 |
| 16. 代码不记决策 | 同机制搜索把已经测量并接受的限制报成新发现 | 用命中函数或模块再查任务、决策、验收记录；区分已知风险和本次新增观察维度 |

## 对照的用途必须写清

不要只写“阴性/阳性对照通过”，写清输入、预期和实际结果，避免名称混淆：

- **已知应命中输入**：用来证明检测器能发现目标错误，之后才有依据相信其沉默。
- **未改动基线**：与修改后的版本使用同一有效环境比较。两侧都失败不自动证明与改动无关；先核实错误是否相同、环境是否复现了权威条件。
- **撤掉修复的版本**：用来证明回归检查确实能区分修复前后，而非始终通过。
- **稳定性检查**：涉及真实超时、并发和子进程时，查看断言依赖事件顺序还是两个计时器的竞争。优先用协议事件、受控时钟或有依据的时间余量。需要施加负载时只在隔离且资源有界的环境执行，不占满用户机器。

同一代码在 PR 与主干上结果不同，可能来自事件载荷、组装版本、环境、依赖或不稳定检查；这只是调查入口，不是任何一个原因的证明。

## 一次失败不一定只有一层原因

修复后仍出现同一表面错误，先比较错误阶段、状态和证据。第一层路由错误消除后，可能才暴露第二层权限问题；不要仅因错误文字相似就回滚有效修复。每一层分别记录“前提—实验—变化”，直到能区分已排除原因和剩余原因。

## 交付证据与承重事实分流

某次运行的日志、截图、测试输出属于执行证据，先落该执行自己的产物。会支撑后续决策或跨任务推理的可复核观察，再按仓库约定进入事实记录。事实写“测到什么、在哪、怎样复核”，不只是“做了什么”。主控和执行者使用同一套权威记录体系，不另建只在聊天里维护的状态表。
